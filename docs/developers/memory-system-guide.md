# Memory System Implementation Guide: Qwen Code

This guide defines the technical architecture and implementation of the `agent-memory` service. The system provides long-term semantic memory for Qwen Code, allowing the agent to store and retrieve context across sessions using vector embeddings.

---

## 1. Introduction

The memory system is implemented as a standalone MCP (Model Context Protocol) server named `mega-memory-manager`. It decouples the storage and retrieval of semantic data from the main CLI process, providing a stable API for memory operations.

---

## 2. System Architecture

### Core Components
- **MCP Server**: The entry point that exposes memory operations as tools (`ingest`, `search`, `reflect`).
- **Transport**: Communication occurs over a Unix Domain Socket (UDS) for low latency and security.
- **Storage**: Uses **Qdrant** as the vector database for storing embeddings and metadata.
- **Embeddings**: A dedicated embedding module transforms raw text into vectors.

### Storage Tiers
The system supports two tiers of memory to balance latency and capacity:
- **Local Tier**: Uses a local Qdrant instance. Optimized for speed and privacy. (Dimension: 384).
- **Cloud Tier**: Uses a remote Qdrant instance. Optimized for large-scale persistence. (Dimension: 3072).

### Security: Peer Verification
To prevent unauthorized access to the memory socket, the server implements **Peer Verification** using `SO_PEERCRED`. The server verifies that the process connecting to the UDS socket has the same User ID (UID) as the daemon process.

---

## 3. Data Lifecycle

### Ingestion Path (`ingest`)
When the agent stores a piece of information:
1. **WAL Logging**: The raw text is immediately appended to a Write-Ahead Log (WAL) file at `~/.local/share/megalonyx/memory/wal.jsonl`.
2. **Vectorization**: The text is passed to the embedding module to generate a vector.
3. **Upsert**: The vector and the serialized `MemoryRecord` are upserted into the specified Qdrant collection.
4. **Confirmation**: The system returns a success status once the data is persistent in Qdrant.

### Retrieval Path (`search`)
When the agent recalls information:
1. **Query Embedding**: The search query is converted into a vector using the same embedding model used during ingestion.
2. **Similarity Search**: A cosine similarity search is performed in the target Qdrant collection.
3. **Thresholding**: Results are filtered based on a minimum relevance score.
4. **Deserialization**: The retrieved payloads are deserialized back into `MemoryRecord` objects and returned to the agent.

---

## 4. Tool Reference

The memory server exposes three primary MCP tools:

| Tool | Input | Output | Description |
| :--- | :--- | :--- | :--- |
| `ingest` | `text`, `tier` | `status`, `id` | Stores text into the specified memory tier. |
| `search` | `query`, `tier` | `list[results]` | Performs semantic recall in the specified tier. |
| `reflect` | `query` | `synthesized_context` | Queries multiple tiers to provide a high-level summary. |

---

## 5. Reliability Mechanics

### Write-Ahead Log (WAL)
To prevent data loss during crashes or network failures, the system uses a WAL.
- **Atomicity**: The WAL ensures that every `ingest` request is recorded on disk before the embedding process begins.
- **Recovery**: On startup, the `recover()` function reads the WAL and replays any records that were not successfully committed to Qdrant.
- **Cleanup**: Once recovery is complete, the WAL is cleared to prevent duplicate ingestions.

## 6. Developer's Guide to Extension

### Adding a New Storage Provider
To replace or add a vector database:
1. Modify `memory_search.py` and `memory_ingest.py` to implement a new client wrapper (e.g., replacing `QdrantClient` with a different provider).
2. Update the `ensure_collection` logic to match the new provider's collection/index creation API.

### Customizing Embeddings
To change the embedding model:
1 Update `memory_embeddings.py` to use a different model or API provider.
2 **Warning**: Changing the embedding model requires a full re-indexing of all existing memory, as vectors from different models are not compatible.

### Advanced Retrieval
To implement hybrid search (combining keyword and semantic search) or reranking:
1 Modify the `search` function in `memory_search.py`.
2 Integrate a reranker model to sort the top-K results returned by Qdrant.

---

## 7. Verification Checklist

- [ ] **WAL Integrity**: Does a crash during `ingest` result in successful recovery on restart?
- [ ] **Tier Isolation**: Does `tier="local"` strictly use the local Qdrant instance?
- [ ] **Peer Verification**: Does the server reject connections from users with a different UID?
- [ ] **Dimension Match**: Do the vectors generated by `memory_embeddings.py` match the collection dimensions (384/3072)?
- [ ] **Recall Precision**: Does a known query return the expected relevant records?
