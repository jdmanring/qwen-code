https://huggingface.co/models

INFERENCE MODELS INDEX
----------------------
https://huggingface.co/inference/models

PRIMARY SERVERLESS API (CORE)
-----------------------------
POST https://api-inference.huggingface.co/models/{model_id}

ROOT API (NOT MODEL SPECIFIC)
-----------------------------
https://api-inference.huggingface.co/

OPENAI-COMPATIBLE ROUTER (LIMITED / UNRELIABLE)
----------------------------------------------
https://router.huggingface.co/v1/chat/completions

NOTE:
This endpoint is NOT equivalent to OpenAI Chat Completions.
It is partial, inconsistent, and model-dependent.

FREE ACCESS
-----------
YES

REALITY OF FREE TIER
--------------------
- Shared GPU queue (multi-tenant execution)
- Strict rate limiting under load
- Cold starts (variable latency spikes)
- 404 when model is not currently deployed/loaded
- 429 when throttled
- 503 when overloaded or queue saturated
- Models may appear/disappear dynamically
- No guaranteed availability or SLA

AUTHENTICATION
--------------
- Hugging Face API token (hf_...)
- Header format:
  Authorization: Bearer HUGGINGFACE_TOKEN

OPENAI COMPATIBILITY
--------------------
NO (core system is NOT OpenAI-compatible)

Mismatch:

OpenAI:
  POST /v1/chat/completions

Hugging Face Serverless:
  POST /models/{model_id}

Implication:
These systems are not interchangeable.
Any OpenAI transport layer will fail against HF serverless.

SERVERLESS MODEL BEHAVIOR
-------------------------
Each model is independently deployed and routed:

- text-generation models:
  input: prompt string
  output: generated text

- instruction/chat-tuned models:
  require model-specific prompt templates
  (no universal chat schema)

- vision-language models:
  multimodal payloads (image + text)

- embedding models:
  separate semantic vector endpoint behavior

IMPORTANT:
There is no unified request schema across models.

MODEL TEMPLATE REQUIREMENT
--------------------------
Chat-style models require:

- model-specific prompt formatting
- tokenizer-based chat templates (when applicable)
- manual message => prompt conversion

This is NOT standardized by the API.

BEST USE CASES
--------------
- low-cost sub-agents
- fallback inference layer
- experimental model routing
- embedding pipelines
- distributed worker systems
- rapid prototyping across open models

STRENGTHS
---------
- largest open-weight model ecosystem
- instant access without deployment
- simple model switching via model_id
- strong coverage (Qwen, LLaMA, Mistral, DeepSeek, StarCoder)
- good for modular AI systems and subagents

WEAKNESSES
----------
- no SLA guarantees
- unstable latency
- frequent 404 / 429 / 503 errors
- dynamic model availability
- inconsistent parameter support across models
- requires retry + fallback architecture
- requires provider abstraction layer

CRITICAL QWEN CODE ISSUE
------------------------

ROOT CAUSE
----------
Qwen Code assumes OpenAI-compatible transport:

  POST /v1/chat/completions

HF serverless requires:

  POST /models/{model_id}

Result:
- all HF requests fail with 404 unless explicitly handled

MODEL VISIBILITY ISSUE
----------------------
Models do NOT appear because:

- no HuggingFace provider registered in runtime
- provider registry does not include "huggingface" type
- UI filters unknown provider types
- config entries are ignored silently if provider is not implemented
- missing factory mapping prevents instantiation

WHAT ACTUALLY MUST CHANGE (CODE REQUIRED)
-----------------------------------------

IMPORTANT:
This CANNOT be fixed by config alone.
It requires runtime code changes.

1. PROVIDER IMPLEMENTATION (REQUIRED)
-------------------------------------
Add new provider class:

HuggingFaceProvider

Must implement:
- request building
- authentication header injection
- model_id routing
- response normalization

Must be registered in:
- provider factory
- provider type enum
- runtime dispatcher

Without this:
config entries are ignored completely

2. TRANSPORT LAYER (CRITICAL)
-----------------------------
Replace OpenAI transport assumption with HF adapter:

Request:
POST https://api-inference.huggingface.co/models/{model_id}

Payload:
{
  "inputs": "<prompt string>",
  "parameters": {
    "max_new_tokens": 4096,
    "temperature": 0.2,
    "top_p": 0.95
  }
}

Notes:
- No messages[] schema
- No system/user roles
- No OpenAI chat format

3. PROMPT ADAPTER (REQUIRED)
----------------------------
Transform:

messages[] => single prompt string

BUT:
Must support model-specific formatting rules:
- Qwen instruction format
- LLaMA chat template
- Mistral instruction style

This is NOT a simple flatten operation.

4. REGISTRY / UI INTEGRATION FIX
---------------------------------
Ensure HuggingFace is included in:

- modelProviders registry
- UI provider dropdown/filter
- runtime provider factory map
- validation schema whitelist

Without whitelist:
models will not appear even if config exists

5. RESILIENCE / RETRY LAYER (MANDATORY FOR HF)
----------------------------------------------
Serverless HF requires fault tolerance:

- 429 => exponential backoff retry
- 503 => retry + alternate model fallback
- 404 => model not deployed; temporarily disable + re-validate later
- timeout => retry once, then failover
- cold start delay => allow extended request timeout window

6. OPTIONAL: MODEL FALLBACK STRATEGY
------------------------------------
Recommended:
- primary model per task
- secondary HF model fallback
- local model fallback (if available)

ARCHITECTURAL CONCLUSION
------------------------
Hugging Face serverless is:

- NOT OpenAI-compatible
- NOT schema-unified
- NOT stable in availability
- NOT deterministic in routing

It IS:
- distributed inference network
- per-model execution endpoint system
- best-effort compute layer for open models

END RESULT TARGET
-----------------
After full implementation:

Hugging Face becomes:
- sub-agent compute backend
- fallback inference provider
- experimental model execution layer
- distributed open-model worker system
- dynamic model routing source for AI workflows
